# CI 실행 정책

일반 PR은 Ubuntu/Python 3.12 한 조합의 대표 오프라인 스모크 검사만 수행합니다.
문서만 변경한 PR은 런타임 테스트와 CUBRID 서버 생성을 생략합니다.
새 모듈을 포함한 모든 드라이버·테스트 경로와 의존성·빌드·스크립트·CI 변경은
고위험으로 보수적으로 분류합니다. 고위험 PR은 Linux/Python 단일 레인에서
기존 전체 오프라인 회귀 검사(커버리지 제외)와 Python 3.14/CUBRID 11.4
대표 통합 검사를 수행합니다.
관련 저장소 도구 검사는 Linux 한 조합으로 수행합니다.

코드가 main에 병합되면 Python 3.12 전체 오프라인 테스트와 기존 95% 커버리지
기준을 적용하고 최저·최신 대표 CUBRID 조합을 검사합니다.
매주 월요일 03:00 UTC에는 최근 7일 변경을 기준으로 같은 대표 검사를 실행합니다.
전체 Python/CUBRID 매트릭스는 자동 야간 실행을 없애고 명시적 수동 실행과
릴리즈 후보의 정확한 SHA 검증에 유지합니다.

PR 스모크 통과는 전체 테스트나 커버리지 검증을 의미하지 않습니다.
기여자는 변경과 관련된 회귀 검사를 로컬에서 실행하고 결과를 PR에 기록해야 합니다.
기존 make test 및 make integration 명령의 범위는 유지합니다.
선택된 필수 검사의 실패·취소·예상치 못한 생략은 최종 게이트를 실패시킵니다.
병합 전에 브랜치 보호 설정이 기존 개별 매트릭스 대신 최종 게이트와 맞는지 확인합니다.
주간 검사 실패는 재실행 또는 수동 검증이 필요합니다.
두 수동 워크플로는 실행 브랜치 커밋과 동일한 전체 `sha` 입력을 요구합니다.
PR 검증에는 `pr_number`도 전달합니다. 실행 전과 최종 게이트에서 열린 PR의
현재 head를 확인하고, 변경된 head나 API 오류가 있으면 실패 처리합니다.
모든 체크아웃은 입력/실행의 고정 SHA를 사용하며 요약에 기록합니다.
일반 CI 수동 실행은 변경 차이가 없어도 대표 런타임·도구 레인을 모두 선택하고,
전체 워크플로 수동 실행은 전체 매트릭스를 선택합니다.
이벤트·ref별 동시 실행 그룹을 분리하며 동일 PR의 이전 실행 취소는 유지합니다.
비용 발생 항목은 아직 확인되지 않았으며 절감 금액을 확정하지 않습니다.

세부 경로 분류와 워크플로우 설명은 [영문 정책](../CI_POLICY.md)을 참고하세요.

버그 탐색은 주 1회 Python 3.12/CUBRID 11.4 대표 조합으로 실행합니다.
TLS·문자셋·공식 드라이버 비교는 PR의 관련 경로에 따라 선택합니다.
